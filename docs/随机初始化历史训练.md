# 随机初始化历史训练

[返回首页](../README.md) · [训练沿革](历史训练沿革.md) · [从零安装与公开权重续训](从零复现训练.md)

本页对应模型的历史训练起点：随机初始化通用策略，再迁移为 decision-v1，分叉为闪刀专家，最后续训到 259M 与 463M。源码、卡组及阶段记录已经公开；本页记录资源准备和各阶段验收进度。

## 1. 取得历史源码与卡组

```bash
git clone https://github.com/zwdmw/GGBOY-ygoagent.git
cd GGBOY-ygoagent
python3.11 scripts/verify_historical_archive.py
```

Git 包含历史 PPO 训练器、共享 ygoai 依赖、迁移前网络、corrected 模型源码、原生环境源码，以及 11,459 副训练卡组、1,433 副验证卡组、1,432 副测试卡组和 15 副官方验证卡组。逐文件身份见 [hash-manifest.json](../third_party/legacy-lineage/docs/hash-manifest.json)。

原始训练器、网络和原生环境按阶段搭配。历史训练器采用原始实验的相对目录布局，准备工程时从归档复制对应版本，并把 game assets、Lua script 和阶段卡组放在原始入口期望的位置。当前整合入口使用 `src/` 与 `resources/` 布局，具体目录关系见[历史归档说明](../third_party/legacy-lineage/README.md)。

## 2. 安装共享游戏资源与早期二进制

先按[从零复现训练](从零复现训练.md#1-准备源码和资源)建立 Linux x86_64 / CPython 3.11 环境，安装固定版本的 JAX/CUDA 依赖和共享游戏资源，再取得历史原生模块：

```bash
python scripts/download_resources.py --install
python scripts/download_historical_resources.py --install
python scripts/verify_historical_archive.py --native
```

历史资源安装器使用 [historical-resources.json](../configs/historical-resources.json) 固定下载大小与 SHA256。两个模块安装到 `native/history/v11/` 和 `native/history/tribute-fix/`。二进制与归档的 Python wrapper、C++ 阶段源码共同使用。

离线安装：

```bash
python scripts/download_historical_resources.py   --archive /path/to/historical-native-resources.tar.gz --install
```

冻结语义表的 SHA256 为 `646b164ddff4169e3379aca3d59fb36f41c4aa7b031c86068f46d00a68657aec`；卡号映射为 `04cb9134b5370b9841f8ee4d969dc519ecb11021f5df3655d0faf9d3c94695aa`。语义表来自共享资源包，历史卡号映射同时保存在归档 `code/library/scripts/code_list.txt`。

| 阶段 | 对应材料 | 验收记录 |
| --- | --- | --- |

| 通用续训与重启 | `records/general-continuation.json`、各次启动参数与 checkpoint 身份 | 精确步数和模型加载已核对；阶段复跑待登记 |
| decision-v1 迁移 | `cleanba.aa1fe2ef.py` / `cleanba.1026a147.py`、迁移前后网络 | 源码备份与迁移边界已核对；迁移重放待登记 |

| corrected 到 259M | `records/corrected/`、corrected 训练器与输入修订环境 | 配置、源文件与 259M 权重身份已核对 |
| 259M 之后的新实验 | 主分支训练入口与公开训练配方 | 原有五份配方的 GPU 短训练及 64 局评估已通过 |

随机初始化的原始配置为 `checkpoint=None`、`tb_offset=0`、seed 0，学习率 0.0003，cluster_uniform 卡组采样，每批 2,048 步。后续重启使用模型参数恢复和新 Adam 状态。专家分叉把计数器重新设为 0，两个计数器的精确边界见[训练沿革](历史训练沿革.md)。

归档为历史阶段的组装和验收提供材料。完整复跑记录应包含：训练器与网络哈希、原生模块及观测版本、语义表和卡号映射、卡组契约、seed、恢复 checkpoint、精确步数、短训练输出和固定协议评估结果。阶段间环境版本与参数变化随对应记录逐项登记。

早期 v11、tribute-fix 和 corrected 参考模块已有固定下载身份；通用续训及专家初期的其余原生修订，随阶段启动记录继续核对和收集。各次重启的精确参数与环境选择也将随复跑配方登记。

## 4. 已完成的核验

- 历史导出 14,499 个文件全部通过原始清单校验；新增 53 个证据文件也全部通过下载后校验。

- corrected 模型实现、PPO 训练器与原生源码分别与所属工程及公开副本核对。
- 本次公开副本按 [hash-manifest.json](../third_party/legacy-lineage/docs/hash-manifest.json) 校验；历史二进制按下载清单校验。

归档完整性验收与历史 GPU 多阶段训练验收分别记录。[全新 GPU 复现报告](全新GPU复现报告.md)记录当前整合入口的实际运行结果；本页表格记录历史阶段的准备与验收进度。
