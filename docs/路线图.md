## 已完成

- 源码与大资源分开发布，固定模型与资源身份，提供 v0.1.0 验收记录。
- 保留 ygo-agent 致谢和上游许可，在首页列出许可范围与待确认事项。
- 提供完整 CPU 首次运行步骤，以及推理、233、训练三条路线。
- 提供资源下载、大小与 hash 校验、缓存复用和离线安装工具。
- 提供中英文首页、FAQ、贡献指南、Issue / PR 模板和轻量 CI。
- 在独立 CPython 3.11 环境安装 CUDA 依赖，完成短训练、注册、GPU 推理与 64 局成对评估，并保存复现记录。

## 优先补齐

| 工作 | 对使用者的帮助 | 完成条件 |
| --- | --- | --- |
| 核实网络组件、权重和卡片资源来源与许可 | 能判断自己计划的使用和再分发是否符合条件 | 附上游链接、版本和条款，更新 NOTICE 与来源清单 |
| 推理包与训练扩展包按用途拆分 | 只体验模型的人减少下载量 | 分包 manifest、hash、离线安装及各路径验收齐全 |
| 验收 Docker 与 systemd | 按文档部署时少猜环境细节 | 在已验证的 CPU / CUDA 环境基础上，补齐部署记录 |
| 更完整的英文使用与贡献文档 | 英文读者可以独立运行和提交问题 | 按命令实际检查并与中文文档同步 |
| 安装 / 233 常见故障的诊断入口 | 出错后知道下一步查看什么 | 给出可执行处理步骤，日志保持脱敏 |

## 后续维护

- 在 Release 说明中清楚列出环境、资源契约变动和升级步骤。
- 收集 Windows / macOS / WSL2 的复现记录，再决定支持范围。
- 为真实训练和对局维护可选验收流程，记录种子、卡组、权重 hash 与结果。
- 为贡献者补充小型、来源清楚的观测和协议 fixtures，减少对大资源的依赖。

首次贡献可以从修复失效链接、校对命令、补充 FAQ 或提供一份已脱敏的安装记录开始。需要修改资源契约或发布结构的工作，建议先用 Issue 说明方案，便于维护者和使用者了解影响。
