# 常见问题

[返回首页](../README.md) · [快速开始](快速开始.md) · [报告问题](https://github.com/zwdmw/GGBOY-ygoagent/issues/new/choose)

## 463M 是模型参数量吗？

它是专家阶段累计训练步数 `463001600`。专项模型为 `464001024` 步；不同模型的身份由配置、sidecar 和 checkpoint SHA256 确定。

## 如何训练到 295M？

`295M` 在本项目中表示专家阶段累计环境步的近似标签。使用 `configs/train/to-295m.json`，
从公开的 `initial-259m`（`259000320` 步）追加 `36003840` 步，按 rollout batch
对齐后得到 `295004160` 步。这个配置从公开权重起点生成约 295M 边界的新 checkpoint，
按输出的精确步数与 SHA256 登记。历史重启恢复模型变量，并重新初始化 Adam。

## 需要什么操作系统、Python 和 GPU？

已完成干净安装验收的是 Linux x86_64 / CPython 3.11，包括 CPU 推理和 GPU 训练、推理。新环境的 CUDA 安装过程和运行结果见[复现报告](全新GPU复现报告.md)。项目声明允许 Python 3.11–3.12，完整运行推荐已验收的 3.11；参考原生二进制面向 Linux x86_64 / CPython 3.11。

Windows 可维护文档与源码。Windows、macOS、WSL2 完整运行尚未验收；选择 WSL2 时可以尝试 Linux 步骤，并在 Issue 中记录结果。

## 第一次推理很慢或暂时没有输出

JAX 第一次要编译计算图，可能需要几十秒到一分钟。运行结束应打印包含 `action` 和模型身份的 JSON。若长时间不结束、进程退出或内存不足，请记录命令、Python 版本、内存情况和错误末尾；不要仅凭首轮编译耗时判断推理失败。

## 下载失败，或大小 / SHA256 校验不通过

执行 `python scripts/download_resources.py --install` 会下载固定的 v0.1.0 资源。工具尊重标准 `HTTPS_PROXY` / `HTTP_PROXY` 环境变量，使用你自己的可用网络或代理后重新运行即可。中断或新下载校验失败的 `.part` 文件会清理，不会当成成功缓存。

如果提示已有缓存校验失败，文件会被保留。将 `release/sky-striker-resources.tar.gz` 移到其他位置后重试，或手动从 [Release](https://github.com/zwdmw/GGBOY-ygoagent/releases/tag/v0.1.0) 下载，再执行：

```bash
python scripts/download_resources.py --archive /path/to/sky-striker-resources.tar.gz --install
```

固定大小与 SHA256 在 [configs/resources.json](../configs/resources.json)。若下载文件和该清单持续不匹配，请报告问题并提供文件大小与 hash。

## 提示 Missing checkpoint、semantic 或其他资源

Git 仓库只包含源码与配置，大资源需单独安装。先确认当前目录是项目根目录、已激活正确的虚拟环境，再执行：

```bash
export YGO_SKY_HOME="$PWD"
python scripts/download_resources.py --install
ygo-sky verify
```

wheel 安装也需要源码目录提供 `configs/` 和 `resources/`。从其他目录调用 CLI 时，将 `YGO_SKY_HOME` 指向该项目的绝对路径，或使用 `ygo-sky --root /path/to/project verify`。

## 已安装资源校验失败 / destination must be empty

工具保留非空的 `resources/`，防止覆盖已有资源。先保存自己的权重和卡组，将原目录移到别处，再安装到空目录；也可使用新的源码副本。不要直接修改 manifest 的 hash 来绕过校验。新增 checkpoint 应用 `ygo-sky register-model` 注册，详见 [模型与资源契约](模型与资源契约.md)。

`python scripts/download_resources.py --verify-only` 可离线检查基线资源；其他模型用 `ygo-sky verify --model specialist-464m`。

## CUDA、jaxlib 或原生库无法导入

先确认 CPython 3.11 / Linux x86_64，使用独立虚拟环境和固定依赖，并运行 `python -m pip check`。按 CPU 快速开始可以检查推理资源。GPU 安装 `.[cuda]`，再执行 `ygo-sky install-native` 和 `python -m pip install --no-deps -e native/ygoenv`，然后按[安装与部署](安装与部署.md)检查 GPU 与引擎导入。

保持 JAX 和 CUDA 库的固定版本，便于匹配历史 ABI。报告安装问题时，附上 GPU 型号、驱动版本、Python/JAX/jaxlib 版本和完整导入错误，参见[安装与部署](安装与部署.md)。

## 233 无法开始对局，或被拒绝卡组

确认服务器为 `s1.ygo233.com:233`、协议为 `0x1362`，双方填写相同的房间名，并有人作为对手加入。默认配置使用兼容卡组 `sky-striker-233.ydk`；冻结训练卡组可能被当前禁限表拒绝。服务器规则会变化，查阅 [233 使用说明](https://ygo233.com/usage)。

查看输出目录的 `status.json`、`result.json` 和错误末尾，确认是连接、房间、卡组检查还是决策阶段出错。CPU 首次编译也可能影响服务器超时。提交日志前移除房间名、账号口令、令牌和私人聊天。完整步骤见 [对战与推理](对战与推理.md)。

## 输出目录已存在

每次训练、评估或对战使用新的 `--output` 目录，例如 `runs/233-second`。运行记录需要独立保存；把有价值的旧记录归档后再操作。

## 能把所有代码、权重和卡片资源都当作 MIT 使用吗？

各组成部分适用自己的许可。根 MIT 仅覆盖原创整合代码与文档；上游声明保留，网络组件、权重和部分资源仍有未明确的许可或来源。查看 [NOTICE](../NOTICE.md) 和 [第三方资源说明](第三方资源说明.md)，贡献者可以帮助补充可靠的来源证据。

## CI 通过是否说明训练、GPU 和真实对局都通过？

CI 检查文档链接、配置格式、Python 语法、无需权重的契约与网络单元测试，以及 wheel 的许可文件。它不下载模型、不训练、不连接真实服务器。完整功能验收范围见 [验收报告](验收报告.md)。

## 如何求助或参与？

## 随机初始化与历史来源

259M 和 463M 记录闪刀专家阶段累计环境步。专家阶段继承通用主线 861,929,472 步权重，并从 0 重新计步。原始随机初始化日志、历史源码、通用卡组划分及续训证据现已核对并公开，见[训练沿革](历史训练沿革.md)与[随机初始化历史训练](随机初始化历史训练.md)。
