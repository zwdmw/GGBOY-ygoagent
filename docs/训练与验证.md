## 模型与训练谱系

`initial-259m` 为 `259000320` 步初始化权重；`base-463m` 为 `463001600` 步基线；`specialist-464m` 为 `464001024` 步专项。
sidecar 保存 `decision-v1` 架构、模型参数、语义形状和训练来源。
训练入口校验输入资源并根据 sidecar 恢复权重，optimizer 重新初始化。259M 之前的通用随机初始化、架构迁移和专家续训资料见[训练沿革](历史训练沿革.md)；阶段资源准备和复跑验收进度见[随机初始化历史训练](随机初始化历史训练.md)。

## 配方

| 配置 | 训练器 | 用途 |
| --- | --- | --- |
| corrected-selfplay.json | cleanba | 修正的专家自博弈 |
| to-295m.json | cleanba | 从公开 259M 权重训练到约 295M 步 |
| mixed-50-30-20.json | cleanba | 镜像/匹配/训练池混合 |
| ppo-continue.json | cleanba_pool | 冻结历史对手 PPO 续训 |
| mirror-specialist.json | cleanba_mirror_pool | 镜像专项与固定锚点对手 |
| smoke.json | cleanba | 32 个额外环境步、两批采样的链路验收 |

`total_timesteps` 是本次额外步数，累计步数通过 sidecar 的 step offset 记录。完整的空目录安装、短跑检查和正式命令见[从零复现训练](从零复现训练.md)。
它必须是 `local_num_envs × num_actor_threads × num_steps × actor_device数量` 的整数倍。
配置中的步数预算记录原配方，执行正式长训练前按目标调整。

`to-295m.json` 的追加步数为 `36003840`，从 `259000320` 到
`295004160`。这是按 `2048` 步 rollout batch 对齐后的约 295M 边界；它提供
公开权重起点和可执行命令，新 checkpoint 按精确步数与 SHA256 登记。

```bash
ygo-sky train --config configs/train/smoke.json --output runs/smoke
python scripts/prepare_opponent_pool.py --manifest configs/train/pools/ppo.json --output runs/pool-ppo
ygo-sky train --config configs/train/ppo-continue.json \
  --pool runs/pool-ppo --output runs/continue
python scripts/prepare_opponent_pool.py --manifest configs/train/pools/mirror.json --output runs/pool-mirror
ygo-sky train --config configs/train/mirror-specialist.json \
  --pool runs/pool-mirror --output runs/specialist
```

使用 `--dry-run` 可检查展开命令而不训练。每次输出目录必须新建；原实验不被覆盖。
历史 PPO 对手池包含 463M/468M 两个成员，镜像专项池包含七个指定成员。
`configs/train/pools/` 固定成员身份，避免把所有归档模型误当成原实验采样池。
训练后 checkpoint 和 JSON sidecar 在 `checkpoints/`，TensorBoard、cluster stats 与 `run.json` 同目录保存。
新模型需用 `register-model` 注册后再供 CLI 推理和接入。

## 数据边界

冻结专家训练目录有 273 个文件、180 种不同文件内容，目标卡组通过重复文件带有 64 次权重。
公开保留该加权行为；`scripts/audit_decks.py` 用于检查内容重复。
通用预训练的 largepool-v3 训练、验证、测试和官方验证划分已保存在[历史归档](../third_party/legacy-lineage/README.md)。专家目标评估卡组参与过训练。
`build_uniform_cluster_split.py` 和 `build_large_pool_split.py` 可为新实验生成划分；历史划分与新划分分别记录来源、契约及哈希。

## 原生评估

```bash
ygo-sky evaluate --config configs/eval/native-mirror.json --pairs 32 --output runs/mirror
ygo-sky evaluate --config configs/eval/native-mirror.json --model base-463m \
  --opponent base-463m --pairs 1 --output runs/control
ygo-sky evaluate --config configs/eval/official.json --pairs 32 --output runs/official
```

每个 pair 包含候选模型坐在双方位置的两局，使用固定种子与独立 LSTM 状态。
结果记录 checkpoint hash、卡组 hash、胜负、长度、超时及推理时间。
官方模型使用较小卡号表，未知卡号/动作/历史需要映射，结果记录映射计数；这限制了比较结论。
少量验收对局只证明链路能够完成，不用于声称强度提升。

## 网络桥与引擎回归

`native_regression.py` 先记录参考引擎决策轨迹，再用重建引擎重放相同动作，逐决策比较观测字节、座位、合法动作数及终局。
`evaluate_network_inputs.py --control` 对训练引擎和桥引擎生成控制结果，`verify_control_parity.py` 生成 proof；网络编码评估需要通过 proof。
网络编码器使用协议可观察信息，无法获取所有原生 engine 查询字段，形状一致不代表输入语义完全相同。

## 语义表生成

```bash
python scripts/card/build_structured_semantics.py \
  --cdb resources/game/assets/locale/en/cards.cdb \
  --script-dir resources/game/script \
  --code-list resources/game/scripts/code_list.txt \
  --output runs/regenerated-semantics.npz
```

本次生成的 `cdb_exact`、`lua_effects` 和 `lua_mask` 与冻结表逐元素一致。
NPZ 元数据、压缩字节和 CDB 全文件 hash 可以不同，模型输入张量一致性另行核验；默认模型继续使用冻结资源。

## 随机初始化与历史来源

259M 和 463M 记录闪刀专家阶段累计环境步。专家阶段继承通用主线 861,929,472 步权重，并从 0 重新计步。原始随机初始化日志、历史源码、通用卡组划分及续训证据现已核对并公开，见[训练沿革](历史训练沿革.md)与[随机初始化历史训练](随机初始化历史训练.md)。
