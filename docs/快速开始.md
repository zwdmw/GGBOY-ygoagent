# 快速开始

[返回首页](../README.md) · [常见问题](常见问题.md) · [安装与部署](安装与部署.md)

本页按 Linux x86_64 / CPython 3.11 编写，这是已完成干净 CPU 安装验收的环境。先完成共同准备，再选择推理、对战或训练路线。Windows、macOS、WSL2 的完整运行尚未验收。

## 共同准备

```bash
git clone https://github.com/zwdmw/GGBOY-ygoagent.git
cd GGBOY-ygoagent
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
export YGO_SKY_HOME="$PWD"
python scripts/download_resources.py --install
ygo-sky verify --model base-463m
python -m pip check
```

资源包约 280 MiB，下载缓存在 `release/`。安装器先检查固定大小和 SHA256，再解包到空的 `resources/`，最后验证基线资源身份。已安装的基线资源校验通过时，重复执行 `--install` 不再下载；已有资源校验失败时保留现场并退出。

离线机器可先复制从 [v0.1.0 Release](https://github.com/zwdmw/GGBOY-ygoagent/releases/tag/v0.1.0) 下载的资源包，再执行：

```bash
python scripts/download_resources.py --archive /path/to/sky-striker-resources.tar.gz --install
# 只检查已安装资源，不联网
python scripts/download_resources.py --verify-only
```

示例中的 `/path/to/` 需要改成文件的实际位置。发布资源和第三方代码的许可范围见 [首页许可表](../README.md#许可范围)。

## 路线一：运行模型

```bash
ygo-sky infer --device cpu --observation resources/example-observation.npz --legal-count 2
```

成功时打印 JSON，包含 `action`、`legal_count`、`inference_ms`、`model_sha256` 和 `global_step`。基线步数是 `463001600`，checkpoint hash 是 `20ddfd6cc92a6d960e617bce2a94ec8ccb50acd785445879b57e1bbe342f1558`。`action` 为合法动作索引，示例观测用于接口验收。

第一次包含 JAX 编译，等待几十秒到一分钟并不罕见，具体时间取决于机器。查看 [首页真实输出](../README.md#cpu-首次运行)。切换模型时先验证它：

```bash
ygo-sky verify --model specialist-464m
ygo-sky infer --model specialist-464m --device cpu \
  --observation resources/example-observation.npz --legal-count 2
```

提供 HTTP 推理时，在当前终端执行：

```bash
ygo-sky serve --device cpu --host 127.0.0.1 --port 8765
```

在另一个终端进入同一个项目目录、激活 `.venv`，执行：

```bash
curl -f http://127.0.0.1:8765/health
python examples/http_infer.py --url http://127.0.0.1:8765 \
  --observation resources/example-observation.npz --legal-count 2 --session demo
```

每场对局使用独立 `session`；服务还提供 `/reset`。对外监听的令牌配置与部署细节见 [安装与部署](安装与部署.md#http-部署)。

## 路线二：接入 233

先完成共同准备。准备一个房间名，让朋友的兼容 YGOPro 客户端加入同一个房间，然后启动模型：

```bash
export YGO_ROOM='your-private-room'
ygo-sky duel --config configs/duel/233.json --device cpu --output runs/233-first
```

默认服务器是 `s1.ygo233.com:233`，协议版本 `0x1362`，卡组是 `resources/decks/sky-striker-233.ydk`（40 主卡 / 14 额外）。这是接入验收用的兼容变体；冻结训练卡组另存为 `sky-striker.ydk`，受当前禁限表限制。客户端需要同房间的对手，单独启动不会自动生成陪练。

已验收的服务器对局使用兼容 GPU 环境。CPU 是无需 CUDA 的启动选项，首次编译可能影响服务器超时；CPU 完整服务器对局尚未验收。有兼容 CUDA 环境时，可安装 `python -m pip install -e '.[cuda]'` 并改用 `--device gpu`，全新 CUDA 安装仍未验收。

`--output` 要使用新的目录名。结束后查看 `runs/233-first/status.json`、`result.json` 和 `decisions.jsonl`；服务器返回录像时会保存 `server-*.yrp`。这些文件用于确认对局是否完整和排查问题。房间口令通过环境变量传入。

指定其他兼容服务器和端口：

```bash
ygo-sky duel --host example.org --port 7911 --version 0x1362 \
  --deck resources/decks/sky-striker-233.ydk --device cpu --output runs/custom-first
```

将 `example.org`、端口和协议版本替换为目标服务器的配置。协议、房名规则、双客户端测试和详细日志说明见 [对战与推理](对战与推理.md)。

## 路线三：继续训练

先完成共同准备。训练还需要训练依赖与参考原生引擎，后者限定 Linux x86_64 / CPython 3.11：

```bash
python -m pip install -e '.[train]'
ygo-sky install-native
python -m pip install --no-deps -e native/ygoenv

# 检查资源与展开的命令；不启动训练
ygo-sky train --config configs/train/smoke.json --platform cpu \
  --output runs/smoke-preview --dry-run
```

`--dry-run` 也需要完整资源。它检查命令与资源，不证明 CUDA 或原生引擎能运行。

在兼容 JAX CUDA 环境中，安装 `python -m pip install -e '.[cuda]'` 后进行短训练：

```bash
ygo-sky train --config configs/train/smoke.json --platform gpu --output runs/smoke-first
ygo-sky evaluate --config configs/eval/native-mirror.json --platform gpu \
  --pairs 1 --output runs/eval-first
```

`smoke.json` 追加 32 个 learner step，是训练链路检查。训练恢复模型权重并重新初始化 optimizer；每次执行使用新的输出目录，保存 checkpoint、sidecar 和运行身份。完整 CUDA 新安装与 CPU 短训练未验收。

继续训练配方、对手池准备和评估解释见 [训练与验证](训练与验证.md)。小样本链路验收不能作为模型强度结论。
