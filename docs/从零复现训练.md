# 从零复现训练

[返回首页](../README.md) · [快速开始](快速开始.md) · [训练与验证](训练与验证.md)

本页给出一条从空目录开始的训练链。源码在 Git 仓库中，模型、卡组、语义表和原生运行资源由固定版本 Release 提供。当前已验证的训练环境是 Linux x86_64 / CPython 3.11 / JAX 0.4.28。实际安装与短训练结果见[全新 GPU 复现报告](全新GPU复现报告.md)。

使用主分支源码执行本页命令，资源仍固定为 v0.1.0。主分支包含新环境安装和 PPO 配方的修复，版本变更见 [CHANGELOG](../CHANGELOG.md)。

## 1. 准备源码和资源

```bash
git clone https://github.com/zwdmw/GGBOY-ygoagent.git
cd GGBOY-ygoagent
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[cuda]'
export YGO_SKY_HOME="$PWD"

python scripts/download_resources.py --install
ygo-sky verify --model initial-259m
ygo-sky verify --model base-463m
ygo-sky install-native
python -m pip install --no-deps -e native/ygoenv
python -m pip check
JAX_PLATFORMS=cuda python -c "import jax, ygoenv; print(jax.__version__); print(jax.devices())"
```

`.[cuda]` 安装训练依赖和固定版本的 JAX CUDA 运行库。上面的检查应显示 CUDA GPU。
创建虚拟环境时使用 CPython 3.11；已安装 Miniconda 的机器也可以用
`~/miniconda3/bin/python -m venv .venv`，先执行 `~/miniconda3/bin/python --version` 确认版本。

资源安装器使用 v0.1.0 的固定大小和 SHA256。离线机器先从 [Release v0.1.0](https://github.com/zwdmw/GGBOY-ygoagent/releases/tag/v0.1.0) 下载 `sky-striker-resources.tar.gz`，再执行：

```bash
python scripts/download_resources.py \
  --archive /path/to/sky-striker-resources.tar.gz --install
```

## 2. 先跑 32 个环境步的链路检查

这一步会加载基线权重、原生环境、语义表和 PPO 更新，生成一个独立的输出目录。它适合确认机器和依赖已经接通：

```bash
ygo-sky train --config configs/train/smoke.json \
  --platform gpu --output runs/smoke
```

只展开命令、不启动训练时：

```bash
ygo-sky train --config configs/train/smoke.json \
  --platform gpu --output runs/smoke-preview --dry-run
```

`smoke.json` 从 `base-463m` 继续 32 个环境步，每批采样 16 步，共两批，输出累计步数 `463001632`。运行结束后查看 `runs/smoke/exit.json` 中的 `exit_code` 是否为 `0`，以及 `runs/smoke/checkpoints/` 中的权重和同名 JSON sidecar。正式运行前为每次实验使用新的 `--output` 目录。

## 3. 从公开的 259M 权重开始训练

`corrected-selfplay.json` 是从 `initial-259m` 开始的完整 CleanBA/PPO 配方，使用专家卡组和固定随机种子：

```bash
ygo-sky train --config configs/train/corrected-selfplay.json \
  --platform gpu --output runs/corrected-selfplay
```

这个配方追加 `699998208` 步，目标累计步数为 `958998528`。机器显存不足时，复制配置后降低并行环境和 `total_timesteps`，先完成短跑，再恢复正式规模；保持 `num_steps`、并行环境数和总步数的整除关系。

## 4. 重现 463M 之后的公开实验路线

历史对手池由 hash 固定的 checkpoint 组成。先按 manifest 准备池：

```bash
python scripts/prepare_opponent_pool.py \
  --manifest configs/train/pools/ppo.json --output runs/pool-ppo

ygo-sky train --config configs/train/ppo-continue.json \
  --pool runs/pool-ppo --platform gpu --output runs/ppo-continue
```

镜像专项使用另一份成员清单：

```bash
python scripts/prepare_opponent_pool.py \
  --manifest configs/train/pools/mirror.json --output runs/pool-mirror

ygo-sky train --config configs/train/mirror-specialist.json \
  --pool runs/pool-mirror --platform gpu --output runs/mirror-specialist
```

专项配方从 `base-463m` 追加 `999424` 步，目标累计步数 `464001024`。每次训练都会保存 `run.json`、checkpoint、sidecar、TensorBoard 和 cluster stats；sidecar 记录模型 hash、累计步数、语义版本和原生引擎 hash。

## 5. 注册和评估新 checkpoint

训练完成后，先使用 checkpoint 的 sidecar 注册模型：

```bash
ygo-sky register-model \
  --checkpoint runs/mirror-specialist/checkpoints/<checkpoint>.flax_model \
  --name my-mirror-specialist
ygo-sky verify --model my-mirror-specialist
ygo-sky evaluate --config configs/eval/native-mirror.json \
  --model my-mirror-specialist --opponent base-463m \
  --pairs 32 --platform gpu --output runs/eval-my-model
```

评估结果保存 checkpoint、卡组、种子、座位交换和推理环境身份。`pairs` 表示换座位的一对对局，结果用于比较同一评估协议下的模型。
